# Lesson authoring and rehearsal

The six code lessons use adjacent Git branches. A lesson starts on `lesson-N`; `lesson-(N+1)` contains its finished code, with `main` as the final solution. The supplied checkout service, operator dashboard, event intake, database access, and model adapter are present from the starter branch. Students live code in `server/agent-workflow.ts` to focus on the harness.

`npm run notes:generate` builds the six lesson pages from `scripts/lesson-data.json`, `scripts/lesson-prose/*.md`, and the exact diffs between adjacent branches. `npm run notes:check` fails if generated pages drift. The concept prose is written in Scott's voice to students and precedes live coding. Code diffs retain unchanged context, green additions, and red removals so an instructor can locate each edit without reconstructing it from memory. Keep cues aligned with the generated hunks. `npm run docs` serves notes locally; `npm run docs:build` checks links and rendering.

For each lesson, rehearse the talking portion, type the diff from the start branch, run `npm run format`, `npm run lint`, and `npm run typecheck`, then test the behavior against a fresh checkout process. Give at least 15 minutes for students to catch up. Do not reset Neon or Inngest merely by switching branches; process state and workflow history are separate from Git. A fresh checkout start creates a new instance and makes the next incident easy to identify.

The required traces are a feature repair, an event wait and recovery, a release rollback with approval, a lost acknowledgement and safe retry, and a dependency help request. Use `/activity` for the agent's saved observe/predict/act/pause feed, `/events` for service notifications, `/` for the inbox, and Inngest for execution checkpoints. Model choice may vary; verify outcome and policy rather than exact tool order. Rehearse with the same real model you plan to use in class.

When changing a lesson branch, regenerate notes and inspect the relevant diff before teaching. The checkout service is supplied code: it may be compact or more complex than the live-coded harness as long as its API contract remains stable. Do not expose its startup fault flag to the model. Keep `.env` and the Neon connection string out of Git.
